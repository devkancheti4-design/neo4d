# AGENTS.md - for any agent (or person) continuing this work

Read this file first. It says what neo4d is, where everything is, how to reproduce every number, what is finished and
what is not, and - most important - the rules that keep the experiments fair. If a rule here and a convenience conflict,
the rule wins. If you are unsure whether something is fair, do not do it; write down the question in your report.

## 1. What neo4d is

A model-free engine that sits beside a language model. The model guesses, reads and writes. neo4d:

- **mutates** code token by token (the standard mutation-testing operators, `neo4d/domain_mutation.py`) and lets
  **tests judge** every variant;
- **searches the neighbourhood** of a model's attempt (`neo4d/local_hints.py`: `explore`, `loop`, deep search);
- **remembers** verified work as plans with the task's names abstracted into slots and replays them without the model
  (`neo4d/local_agent.py`: `abstract`, `replay`, `Brain`);
- decides what it trusts with **integer laws**, chiefly **RELATE v2** (`neo4d/kernels/relate_v2.c`), an 8-bit,
  branch-free law checked on all 2^32 inputs (UBSan, CBMC) and against its principles on every reachable input.

The laws in `neo4d/kernels/` were **authored externally** from the prompts in `prompts/`; this repository judges,
proves and uses them. **Never edit a kernel.** A changed law is a new version (new file, new prompt) and must be judged
again (`neo4d judge`, `neo4d relate-v2`).

The paper: `paper/neo4d.tex` -> `paper/neo4d.pdf` ("Guess Close, Search Exact"). The README's sections summarise every
result with the command that produced it.

## 3. Setup

```bash
python3.11 -m venv .venv && source .venv/bin/activate
pip install -e .
sh scripts/fetch_bench.sh            # QuixBugs, click, BugsInPy / Defects4J / Defects4C metadata, fluid-router, fluidnet -> bench/
pytest -q tests                      # everything should pass
```

Local models are served by ollama (`OLLAMA_URL`, default `http://localhost:11434`). The paper used `phi4-mini`,
`gemma3:4b` and `qwen3.5:4b`. The paper builds with `tectonic paper/neo4d.tex`. CBMC is needed only for the proof
commands.

## 6. Rules for fair experiments - follow all of them

**Comparisons**
1. Compare conditions on **the same tasks, the same seeds, and the same budget of model calls**. Count every call,
   including reflections, localisation and reproduction calls. A method that uses more calls must say so in the table.
2. The first attempt is greedy (temperature 0); later attempts sample (0.8). Use the same settings in every condition.
3. Change one thing between two conditions. If neo4d's condition also gets extra information (evidence, marks), that is
   a separate condition with its own row.

**Information**
4. **Never use evaluation information in a solver**: hidden or extended tests, gold patches, `FAIL_TO_PASS` /
   `PASS_TO_PASS` lists, `hints_text`, oracle files, a benchmark's answers. In the QuixBugs experiments the tests are the
   task's own check, given to every solver alike - state that wherever it applies.
5. A model under test (including Claude subagents) gets only the task and the tools. Subagents must act only through
   the command interfaces (`--agent-start/--agent-act`, `--hints-start/--hints-submit`, `--search-start/--search-pick`)
   and must not read files, the checker or other runs. Their exact prompts are in `docs/SUBAGENT_PROMPTS.md`; reuse them
   unchanged - a changed prompt is a new condition.
6. Hide anything that lets a model recall a benchmark when the test is about reasoning (the hard bugs use opaque
   function names; never print a program's real name).

**Design and reporting**
7. Do not tune on the data you report. Design on a design set; run held-out sets once with the design fixed; record
   every variant you tried, with its numbers, in the results file (a "what was tried" table).
8. Report negative results with the same care as positive ones. Never drop a run, a seed, a model or a task after
   seeing its result. If a run crashes, rerun it whole and say so.
9. Keep raw data: per-task outcomes and traces go into `results/data/`. Every number in `results/` and the paper must
   come from a command in this repository.
10. Use statistics proportionate to the claim: seeds, 95% intervals, paired tests (exact McNemar, sign-flip
    permutation). Do not claim a difference of a few tasks without them.
11. Make runs deterministic where possible (fixed seeds, fixed tie orders - a Python `set` iterates in a different
    order in every process). Name every remaining source of noise (the model server, timeouts under load).
12. Claims must match evidence. Do not write that neo4d reaches frontier level, saves stated sums of money, or that the
    whole system converges; write exactly what was measured or proved, and what was not.

**Ownership**
13. Never enter or handle credentials (accounts, API keys, tokens, SSH secrets). Publishing (Zenodo, a leaderboard pull
    request, making the repository public) is the owner's action; prepare everything, then hand it over.
14. Downloads (benchmarks, packages, models) need the owner's OK; say what, from where and how large.
15. Commit messages end with a co-author line for the agent that did the work; do not commit `bench/`, `.build/`,
    `training/` or logs.

## 7. Pitfalls already met (and fixed)

- macOS temp folders resolve to `/private/var/...`: resolve paths before comparing (`Sandbox` does).
- The local model server answers HTTP 500 under concurrent load: every call retries with backoff; run at most about
  three model-calling processes at once; run long jobs under `nohup` so a session restart does not kill them.
- A set's iteration order changes per process: sort ties explicitly (plans are ranked by level, success, length, text).
- QuixBugs' correct programs end with a docstring holding alternative implementations: grep finds code in it;
  keyword counts must use real code tokens (`tokenize`), and the harness strips or ignores those docstrings.
- The bug-stream harness places a model's corrected line over the line it most resembles; `return x -> return None`
  bugs are lost that way for every writer (ceiling 166/176) - report the ceiling.
- `tests/` rebuilds `.build/agent_project`: do not run the tests while an agent experiment that uses it is running.
- A small model's attention is diluted by long evidence (16 vs 20 of 31): prefer neo4d doing work over advising.
