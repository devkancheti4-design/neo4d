How it works

It learns from your tests.
Nothing else.

Three steps run in a loop, each decided by its own law. Your test suite is the only judge of right and wrong.

1 · LEARN

Experiments

It runs small, targeted edits against your suite and keeps the ones that teach it something. On click, five trials gave five worked examples in twenty suite runs.

pick · harvest

2 · RELATE

Patterns as neurons

Each fix pattern has a strength. It grows when the pattern predicts a real fix before seeing it, and fades when the pattern keeps firing without being right.

relate

3 · SHIP

Only what agrees

A fix ships when the suite was failing, turns stably green, and no other candidate also passes. Anything less is refused, with the reason.

ship

Proof

Proved, not promised.

Each law is a few dozen machine instructions with no branches. A judge checks it against its specification on every possible input, and a model checker proves the routing laws outright. A law that fails one case does not ship.

Questions

Good to know.

Is there AI in it?

No neural network and no training. Every decision comes from an integer law you can read, and the judge checks each one on every input before it ships.

Is every fix mathematically proven?

The decision logic is. Each fix is verified by your own test suite: it must turn a failing suite stably green, and no other candidate may pass as well. When the evidence is thin, it asks for one more deciding test instead of shipping.

How much will it fix?

About 10–17% of real bugs today, and more as it sees more of your project. The share of genuinely new fix patterns falls with experience, from 47% to 18% across 706 real fixes.

Which languages?

Python first. Its patterns carry over: taught only Python, it covers 93% of a C mutation domain, and 88–90% for C++ and Java, where precision is lower.

What do I need to run it?

Python 3, a C compiler and your test suite. CBMC is optional, for running the formal proofs yourself.
