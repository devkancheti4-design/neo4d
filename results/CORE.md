# Is neo4d core-level? The same core on domains that are not code

Generated by `neo4d/core_experiment.py`. The core (`neo4d/core.py`: the loop, the search, verified memory and the RELATE v2 law) is the same file for every domain; each domain (`neo4d/domains/`) supplies only how to ask a model, read its answer, check, vary and abstract a candidate. Every method may use at most 4 model calls and 400 checker calls per task. Intervals: 95% bootstrap over tasks of the per-task success rate averaged over seeds; p: a paired sign-flip permutation test. The 4D routers are not used: these domains give them nothing to route yet.

## Design run, seed 98 (15 tasks; for debugging - not a result)

The second design run, after these changes made because of the first (seed 99, recorded in `.build/core_runs.json` under `design|`, with 5 numbers and up to 6 blocks): phi4-mini solved nothing on its own in either domain - its Countdown answers miscalculated (it wrote `(50 - 1) * 7 + 25 - 9 = 83`; that is 359) and its plans moved bottom blocks first and then repeated themselves for dozens of lines - so there was no near-miss for neo4d to repair, and neo4d's search alone did as well (8 of 15 in each domain). Changes: Countdown with 4 numbers and targets up to 200, the answer asked for without its value; Blocks with 3-5 blocks, the top blocks named in the prompt, replies read up to three moves per block, and a checker that skips an illegal move and penalises it instead of stopping at it; a check budget of 100 per task as the main setting. Every method gets the same prompt and checker. Run 98 was interrupted; it also showed that the core searched only two changes deep around each model attempt while search alone searched four - an inconsistency, fixed (four for both) before it was run again.
