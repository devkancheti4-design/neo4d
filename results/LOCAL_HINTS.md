# Bugs a model never solved: neo4d mutates, the model reasons, round after round

Generated by `neo4d/local_hints.py`. neo4d cannot reason, but it can experiment: on a broken program it tries every single-token change its mutation operators know, runs the tests on each, and reports what it found. This file tests how that should be exchanged with a model - nothing is trained; everything goes through the prompt.

**The bugs.** The real QuixBugs bugs - written by people, not by neo4d's operators - in the 31 programs whose tests are JSON cases. **neo4d alone** (a mutation that passes every test) fixes **5 of 31**; the other 26 are the ones that matter.

## The first design: neo4d's evidence up front, 3 rounds (phi4-mini)

The model was given neo4d's evidence about the original bug as a paragraph, then up to 3 tries; the exchange mutated each attempt. This run was stopped after phi4-mini, when the loop below replaced it; the numbers are from its log.

| phi4-mini | fixed of 31 |
|---|---|
| model alone, one try | 11 |
| model + tests, up to 3 tries | 20 |
| model + neo4d's evidence, one try | 12 |
| model + neo4d's evidence + tests, up to 3 tries | 16 |
| exchange, 3 rounds, evidence up front | 18 |

The paragraph of evidence **hurt** (16 against 20): a small model's attention is diluted by it. The two designs below answer this - the loop drops the up-front evidence and mutates the model's own attempts; the attention test shows the evidence as marks in the code instead.

## A large model in the exchange

Claude Haiku, run as subagents, on the same bugs, at most 3 submissions a bug. **Haiku + tests**: after each submission it is told the test results only. **neo4d + Haiku exchange**: it starts with neo4d's evidence, and after each submission neo4d mutates the program, ships any variant that passes, or reports back what it found.

| solver | all 31 bugs | the 26 neo4d cannot fix alone | fixed at the first submission | submissions (model calls) | fixed by neo4d mutating the model's program |
|---|---|---|---|---|---|
| Haiku + tests | 31/31 | 26/26 | 31 | 31 | 0 |
| **neo4d + Haiku exchange** | 31/31 | 26/26 | 31 | 31 | 0 |

## A large model in the exchange: bugs it cannot recall

Each correct program obfuscated (hash-named variables, no docstrings or comments), its function renamed to an opaque name, and broken by **two** faults on two lines: each fault alone fails the tests, and no single-token change fixes the pair, so neo4d alone fixes none. The model must reason from the code and the tests.

Claude Haiku, run as subagents, on the same bugs, at most 3 submissions a bug. **Haiku + tests**: after each submission it is told the test results only. **neo4d + Haiku exchange**: it starts with neo4d's evidence, and after each submission neo4d mutates the program, ships any variant that passes, or reports back what it found.

| solver | all 29 bugs | the 29 neo4d cannot fix alone | fixed at the first submission | submissions (model calls) | fixed by neo4d mutating the model's program |
|---|---|---|---|---|---|
| Haiku + tests | 29/29 | 29/29 | 29 | 29 | 0 |
| **neo4d + Haiku exchange** | 29/29 | 29/29 | 27 | 31 | 0 |

## neo4d searches deep, the model only filters

On the 29 hard bugs (two faults each, obfuscated, renamed). neo4d generates and tests every program: one change deep, then deeper from the candidates kept, up to 4 changes. **Blind**: it keeps the 3 that pass the most tests. **Haiku as the filter**: at each level Haiku is shown the 12 most promising candidates and picks up to 3 to go deeper - it never writes code. 18 bugs are reachable by neo4d's operators (each fault is one of its changes undone); for the other 11, a fault is outside what it can change, and no search over its changes can fix them.

| solver | fixed | reachable (18) | unreachable (11) | model calls | test runs |
|---|---|---|---|---|---|
| neo4d deep search, blind (keeps the 3 that pass most tests, each level) | **14/29** | 13 | 1 | 0 | 5,815 |
| **neo4d deep search + Claude Haiku as the filter** | **17/29** | 16 | 1 | 37 | 2,316 |
