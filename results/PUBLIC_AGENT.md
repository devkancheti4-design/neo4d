# Public repositories: neo4d beside a large model on a coding agent's everyday work

Generated by `neo4d/public_agent.py`, which describes the repositories (boltons 4e5faa3, click 2247b35, toolz 451af60), the six kinds of task and their checks. 98 tasks in one seeded stream (results/data/public_runs/tasks.json); every task's gold solution was applied and accepted before any run. The Claude runs' traces are in results/data/public_runs/; their scores are made again with `python -m neo4d.public_agent --fetch` then `--agent-score sonnet,haiku` (each working copy is rebuilt by replaying its trace; this judged all 196 tasks exactly as the live copies did).

What this does not show: one run per model; the savings come from work that recurs (renaming a parameter, listing callers), while a fix or a new parameter needs the model every time; the tasks are generated from the repositories' code, not taken from their issue trackers. A rename touching more files than 12 actions can edit is out of an agent's reach but not of a plan that repeats an edit over the files a search found. The agents used the tools in their own ways: one wrote a helper script and ran it through the test action to count keywords; some answered counts partly from memory of the projects' sources.
