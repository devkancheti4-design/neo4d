# A small local model doing multi-step work, with neo4d as its brain

Generated by `neo4d/local_agent.py`. Local model: **phi4-mini** (ollama, on this machine). A real project - 31 QuixBugs programs as modules, one test file each - and **85 tasks** of six kinds, the everyday work of a coding agent, in one seeded stream. Each needs several tool calls (ls, read, grep, replace, write, test, done - Claude's tools, reduced) and is accepted only by a check: the tests, plus a check of the result itself. Each kind is phrased two ways.

**What this does not show.** The project is small and the six kinds of task recur, so a plan learned once is used many times - work that repeats is where a learned plan pays. A plan is matched to a task by its phrasing with the names taken out, so each phrasing is learned separately. The check is the judge for every solver; in real use the check is the tests and whoever asked for the work.

## Large models as the agent

Claude Haiku and Claude Sonnet, each run as subagents working through the same stream with the same tools, one action per command, at most 10 actions a task, one try. **neo4d + model**: in stream order, neo4d runs its trusted plans that need no model call; the model's own work counts for every other task, and neo4d learns from it. Model actions are the large model's turns - each one a call. Plans of equal strength are tried in a fixed order, so these numbers reproduce exactly (the phi4-mini run above was made before that fix, with such ties in arbitrary order). The raw runs are in results/data/agent_runs/.
