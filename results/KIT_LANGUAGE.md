# Kit 2 - one numbering across languages (QuixBugs, Python and Java)

Generated by `neo4d/kit_language.py`. The same 40 bugs in both languages; each buggy file against its correct version, with comments, docstrings, imports and whitespace ignored. Patch level: no Java runtime here, so the Java tests are not run.

| | Python | Java |
|---|---|---|
| the fix replaces one line | 36 | 30 |
| the fix only ADDS a line (missing logic) | 4 | 4 |
| the fix spans several lines | 0 | 6 |
| **the vocabulary generates the fix exactly** | **4** | **4** |

Fix shape agrees across the languages on 34 of 40 programs. Generated in both: **3**, by the same class - the same 4-bit kind - in **3 of 3**. Python only: 1; Java only: 1.

| program | Python | Java | kind |
|---|---|---|---|
| find_first_in_sorted | `while lo <= hi:` -> `while lo < hi:` | `while (lo <= hi) {` -> `while (lo < hi) {` | strictness |
| knapsack | `if weight < j:` -> `if weight <= j:` | `else if (weight < j) {` -> `else if (weight <= j) {` | strictness |
| next_palindrome | `return [1] + (len(digit_list)) * [0] + [1]` -> `return [1] + (len(digit_list) - 1) * [0] + [1]` | not generated (one-line) | len-as-last-index |
| next_permutation | not generated (one-line) | `if (perm.get(j) < perm.get(i)) {` -> `if (perm.get(j) > perm.get(i)) {` | flipped-comparison-direction |
| quicksort | `greater = quicksort([x for x in arr[1:] if x > pivot])` -> `greater = quicksort([x for x in arr[1:] if x >= pivot])` | `} else if (x > pivot) {` -> `} else if (x >= pivot) {` | strictness |

Where the languages differ:

- next_palindrome, Java: `otherwise.addAll(Collections.nCopies(digit_list.length, 0));` -> `otherwise.addAll(Collections.nCopies(digit_list.length-1, 0));`
- next_permutation, Python: `if perm[j] < perm[i]:` -> `if perm[i] < perm[j]:`

Exact text undercounts: in Python, next_permutation and levenshtein are repaired by their own tests in `results/QUIXBUGS.md` with an equivalent rewrite (`perm[j] > perm[i]` for the reference's `perm[i] < perm[j]`; `0 +` for the reference dropping `1 +`). Counting next_permutation, the same kind fixes the same bug in both languages in 4 programs; next_palindrome is the one real gap - len-as-last-index rewrites `len(x)`, and Java spells it `x.length`.

**What this shows.** A class is a token rewrite, so where a bug is written with the same tokens in both languages the same kind generates its fix; the code-to-kind map carries over. It does not carry where the languages spell the construct differently, and nothing in the vocabulary generates an added line - those need fluidnet's omission path.
